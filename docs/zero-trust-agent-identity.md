# GraphOath — Zero-Trust Workload Identity Architecture (SPIFFE/SPIRE)

This document specifies **GraphOath's Zero-Trust Agent Identity Layer**, which binds cryptographic agent workload credentials (SPIFFE IDs and short-lived SVID tokens) to DataHub metadata operations and Custody receipt hashes.

---

## 1. The Workload Impersonation Risk

In multi-agent environments, agents often share long-lived API tokens or service accounts. If an agent process is compromised or misconfigured, it can impersonate another agent and execute unauthorized actions against DataHub.

GraphOath eliminates shared tokens by requiring **SPIFFE/SPIRE Workload Identity Verification**.

---

## 2. SPIFFE/SPIRE Integration Sequence

```
 ┌─────────────────┐       1. Request SVID       ┌──────────────────┐
 │ AI Agent Worker ├────────────────────────────►│  SPIRE Agent     │
 └────────┬────────┘◄────────────────────────────┤  Workload API    │
          │                2. Cryptographic SVID └──────────────────┘
          │                   (SPIFFE ID: spiffe://example.com/agent/deposition)
          │ 3. Proposed Action + SVID Header
          ▼
 ┌──────────────────────────────────────────────┐
 │          GraphOath Identity Verifier         │
 │  - Validates SVID x509 Certificate Chain     │
 │  - Binds SPIFFE ID to Receipt Hash          │
 └──────────────────────┬───────────────────────┘
                        │
                        ▼
 ┌──────────────────────────────────────────────┐
 │   DataHub Action + Signed Custody Receipt    │
 └──────────────────────────────────────────────┘
```

## 3. Cryptographic Binding in Receipts

Every receipt generated by GraphOath includes the verified workload identity:

```json
{
  "receipt_id": "rcpt_98f4a12b-7c3e-4b9d-a8f1-2e6b5c4d3a01",
  "agent_identity": {
    "spiffe_id": "spiffe://graphoath.io/agent/deposition-v1",
    "svid_serial": "4729103859281740291",
    "issuer": "spiffe://graphoath.io/ns/prod"
  },
  "ledger_hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
}
```

This guarantees that **every action in the Custody ledger is cryptographically non-repudiable and tied to a verified container/process identity**.
